# 2.2 Java RMI Callback - finalno objasnjenje

Ovaj fajl spaja prezentaciju `2.2 Java RMI Callback.md`, tvoje beleske i sablon iz primera `CalculatorAccCallback` i `Chat` iz `.zips`.

## Najkraci mentalni model

Callback znaci da server obavestava klijenta kada se desi dogadjaj. To radi tako sto i klijent napravi remote objekat. Klijent taj objekat prosledi serveru kroz `register`, a server kasnije poziva metode tog objekta.

U obicnom RMI toku:

```text
Klijent -> Server
```

U callback toku:

```text
Klijent -> Server
Server -> Klijentov callback objekat
```

## Slajd 1 - Naslov

Tema je RMI Callback. To je prosirenje osnovnog RMI sablona.

Za ispit: callback nije posebna tehnologija. To je jos jedan remote poziv, samo u suprotnom smeru.

## Slajd 2 - Ideja callback-a

Bez callback-a klijent mora stalno da pita server da li se nesto promenilo. To se zove polling.

Sa callback-om server sam pozove klijenta kada se desi dogadjaj.

Primer iz beleski: ako vise klijenata prati isti akumulator, nije dobro da svako stalno zove `getAcc()`. Bolje je da server obavesti sve klijente kada se `acc` promeni.

Za ispit: recenica koju treba zapamtiti je: callback je serverska akcija obavestavanja klijenta da se dogadjaj desio.

## Slajd 3 - Callback implementacija

Callback resenje ima tri koraka:

1. Klijent kreira remote callback objekat.
2. Server ima metodu `register` kojom prima callback referencu.
3. Kada se dogadjaj desi, server prolazi kroz registrovane callback objekte i poziva njihovu metodu.

Minimalan callback interfejs:

```java
import java.rmi.*;

public interface Callback extends Remote {
    public void changed() throws RemoteException;
}
```

Za ispit: callback objekat mora biti remote zato sto ga server poziva iz druge JVM.

## Slajd 4 - Whiteboard primer

Whiteboard primer govori o vise korisnika koji dele zajednicku tablu. Server cuva oblike, a kada novi oblik stigne, svi zainteresovani klijenti treba da saznaju za promenu.

Bez callback-a klijent mora stalno da pita:

```text
Da li ima nova verzija?
Da li ima nova verzija?
Da li ima nova verzija?
```

Sa callback-om server pozove klijente kada se verzija promeni.

Za ispit: ovaj primer je isti obrazac kao chat, aukcija, rezultati utakmica ili generisanje prostih brojeva po elementima.

## Slajd 5 - Resenje sa i bez callback-a

Resenje sa callback-om dodaje:

- callback interfejs;
- `register(callback)`;
- `unregister(callback)`;
- listu registrovanih klijenata na serveru.

Iz primera `.zips/CalculatorAccCallback`:

```java
public void register(Callback cb) throws RemoteException;
public void unregister(Callback cb) throws RemoteException;
```

Iz primera `.zips/Chat`:

```java
public void register(String username, ChatCallback cb) throws RemoteException;
public void unregister(String username) throws RemoteException;
```

Razlika je samo u tome da chat pamti callback po korisnickom imenu.

## Slajd 6 - Callback interfejs

Primer sa slajda:

```java
public interface IWhiteboardCallback extends Remote {
    void callback(int version) throws RemoteException;
}
```

Pravila su ista kao za svaki remote interfejs:

- nasledjuje `Remote`;
- remote metoda baca `RemoteException`;
- parametri i povratne vrednosti moraju biti pogodni za RMI.

Za ispit: ako u zadatku pise "klijent treba da bude obavesten", skoro sigurno ti treba callback interfejs.

## Slajd 7 - Callback implementacija u klijentu

Callback implementacija se nalazi na strani klijenta, ali je remote objekat.

Sablon iz `.zips/CalculatorAccCallback`:

```java
public class CallbackImpl extends UnicastRemoteObject implements Callback {
    protected CallbackImpl() throws RemoteException {
        super();
    }

    public void accChanged() throws RemoteException {
        getAcc();
    }
}
```

Bitna stvar iz beleski: ako je callback klasa unutrasnja klasa klijenta, ona moze da pozove metode spoljasnje klase, na primer `getAcc()`.

Za ispit: klijent prvo dobije stub servera, zatim napravi callback objekat, pa ga registruje.

## Slajd 8 - Registracija i odjava

Server cuva listu callback objekata:

```java
private ArrayList<Callback> clients = new ArrayList<Callback>();
```

Registracija:

```java
public synchronized void register(Callback cb) throws RemoteException {
    clients.add(cb);
}
```

Odjava:

```java
public synchronized void unregister(Callback cb) throws RemoteException {
    clients.remove(cb);
}
```

Kada se dogadjaj desi:

```java
for (Callback cb : clients) {
    cb.changed();
}
```

Za ispit: `synchronized` nije glavna poenta, ali je korisno kada se deli lista callback objekata.

## Minimalan callback sablon za ispit

Remote servis:

```java
import java.rmi.*;

public interface Servis extends Remote {
    public void register(Callback cb) throws RemoteException;
    public void promeniStanje() throws RemoteException;
}
```

Callback interfejs:

```java
import java.rmi.*;

public interface Callback extends Remote {
    public void changed() throws RemoteException;
}
```

Serverska implementacija:

```java
import java.rmi.*;
import java.rmi.server.*;
import java.util.*;

public class ServisImpl extends UnicastRemoteObject implements Servis {
    private ArrayList<Callback> callbacks = new ArrayList<Callback>();

    public ServisImpl() throws RemoteException {
        super();
    }

    public synchronized void register(Callback cb) throws RemoteException {
        callbacks.add(cb);
    }

    public void promeniStanje() throws RemoteException {
        for (Callback cb : callbacks) {
            cb.changed();
        }
    }
}
```

Klijent:

```java
import java.rmi.*;
import java.rmi.server.*;

public class Klijent {
    private Servis servis;

    public Klijent() {
        try {
            servis = (Servis) Naming.lookup("rmi://localhost:1099/Servis");
            Callback cb = new CallbackImpl();
            servis.register(cb);
        } catch (Exception e) {
        }
    }

    public class CallbackImpl extends UnicastRemoteObject implements Callback {
        public CallbackImpl() throws RemoteException {
            super();
        }

        public void changed() throws RemoteException {
            System.out.println("Promena na serveru.");
        }
    }
}
```

## Kako prepoznati callback zadatak

Callback ti treba kada tekst zadatka kaze nesto poput:

- server obavestava klijente;
- korisnici se pretplacuju;
- klijent treba da bude u toku sa promenama;
- svaki element se vraca klijentu cim se generise;
- poruka se dostavlja drugim klijentima;
- rezultat se javlja pretplacenim korisnicima.

Ako klijent samo trazi podatak na zahtev, callback nije potreban. Ako server treba sam da javi promenu, callback jeste potreban.
