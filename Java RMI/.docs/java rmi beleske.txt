iz klijenta, lokalna metoda zeli da pozove neku sa servera, to radi preko stub-a, on mora da zna IP adresu i port gde se nalazi objekat (sa metodama) koji je na serveru i mora da zna njegov ObjectId,. U serveru se trazi skeleton, ako u serverskom delu imamo npr Object1 i Object2  skeleton ce znati koji se ObjectId prosledi i onda ce naci odgovarajuci Object koji trazimo (radi njegovog stanja/metoda).

JAVA RMI je enkapsulirao Client STUB i Server Skeleton,to je apstraktno i mi nemamo pristup pozadini. Mi samo pisemo JAVA RMI KLASE, koje su slicne kao klasicne za OOP.

Tako registruje jedan objekat, drugi npr ce da bude na localhost:1992, ip adresa i port mogu biti isti ali ovde je /obj2.

mora da se malo razlikuje od standardnog java oo interfejsa

	//bitno je da sve metode budu javne
	public metod() throws java.rmi.Remote.Exception;
} 

ovo je samo interfejs, njega ne mozemo da instanciramo vec moramo da napravimo klasu koja enkapsulira objekat koji nam treba, on implementira ovaj interfejs

ta klasa mora da nasledi UnicastRemote klasu
public class Class1 extends UnicastRemoteObject implements Interfejs{
	public metoda1()
